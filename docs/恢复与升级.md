# 备份、恢复与升级

## 备份

本地运行 `npm run backup`；systemd 部署执行 `sudo systemctl start yunjian-backup.service`。定时器每日北京时间 04:20 后随机延迟至多五分钟运行，保留最近 7 个有成功备份的日期。

备份在数据目录的 `backups/yunjian-YYYY-MM-DD.sqlite`，目录 700、文件 600。每次备份都通过 SQLite 在线备份接口生成一致副本，然后在副本中检查完整性、外键和所有账户凭据能否用当前密钥解密；副本中的网页会话被清除。整个过程不需要停止采集。

数据库中的平台凭据依旧为加密内容，副本不包含原加密密钥。需要将 `.env` 或服务器上的 `runtime.env` 单独保存在受保护位置。两者同时泄露就失去凭据保护；密钥丢失则无法恢复平台凭据。

同机备份无法覆盖整台服务器丢失的情况。需要异地恢复能力时，应另外配置受保护的传输与保留策略，不要把备份放入 Git 仓库。

## 恢复

1. 先保存当前数据库与配置，确认选定副本通过了检查，且持有匹配的原始加密密钥。
2. 暂停本项目的备份 timer，只停止本应用。不要操作其他服务或现有 HTTPS 入口。
3. 在隔离临时目录检查副本的 `PRAGMA integrity_check` 和凭据解密结果；不要通过打印凭据来确认。
4. 应用完全停止后，将原数据库及其 `-wal` / `-shm` 文件一并保存到恢复目录，再安装选定副本为数据目录下的 `yunjian.sqlite`。禁止将旧 WAL / SHM 与恢复后的数据库混用。
5. systemd 部署时，数据库归属 `yunjian-monitor:yunjian-monitor`，权限 600。只在配置或密钥丢失时恢复原配置，配置仍为 root 600。
6. 启动本应用与备份 timer，验证健康检查、管理登录、设备采样和曲线。备份不含有效网页会话，恢复后需重新登录。

## 升级

先运行并验证备份，暂时停止备份 timer。将新源码解压到新的程序目录，保留原程序目录、配置、Node.js 运行时与数据。仅切换本项目程序目录并重启本应用，验证后再恢复 timer；失败时切回旧程序。

当前版本新增表采用 `CREATE TABLE IF NOT EXISTS`，保留原有账户和分钟快照，不虚构旧记录的峰值。每次升级仍应查看具体数据库变更，不能假设任何未来版本都支持直接降级。

不要重新运行初始化工具覆盖现有加密密钥。`deploy/install-isolated.sh` 只适用于新安装，会拒绝覆盖现有目录。

SQLite 在线备份：[Node.js 24 文档](https://nodejs.org/docs/latest-v24.x/api/sqlite.html#sqlitebackupsource-db-destination-options)、[SQLite 文档](https://sqlite.org/backup.html)。
