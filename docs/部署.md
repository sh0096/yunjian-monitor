# VPS 与 HTTPS 部署

以下为 Ubuntu 22.04+ / Linux x86_64 的参考流程。仓库提供独立服务账户、数据目录及资源限制；安装脚本不修改 SSH、防火墙、反向代理或其他服务。已有安装会拒绝覆盖，升级请参阅[恢复与升级](恢复与升级.md)。

## 1. 准备源码包

在已克隆仓库的电脑上执行：

```sh
git archive --format=tar.gz --output=yunjian-source.tar.gz HEAD
scp yunjian-source.tar.gz YOUR_SSH_USER@YOUR_SERVER:/tmp/yunjian-source.tar.gz
scp deploy/install-isolated.sh YOUR_SSH_USER@YOUR_SERVER:/tmp/yunjian-install.sh
```

`YOUR_SSH_USER` 和 `YOUR_SERVER` 使用自己的连接信息。源码包来自 Git 已提交文件，不能包含 `.env`、数据库、备份或私钥。

在服务器确认 8787 未占用、安装了 `curl python3 tar iproute2` 等依赖，阅读 `/tmp/yunjian-install.sh` 后执行：

```sh
sudo sh /tmp/yunjian-install.sh
```

脚本下载并校验固定版本的官方 Node.js 24.22.0，创建以下专用路径和服务：

| 内容 | 位置 |
|---|---|
| 应用与 Node.js | `/opt/yunjian-monitor` |
| 配置，root 600 | `/etc/yunjian-monitor/runtime.env` |
| 数据，专用账户 700 | `/var/lib/yunjian-monitor` |
| 应用服务 | `yunjian-monitor.service` |
| 每日备份 | `yunjian-backup.service` / `.timer` |

首次安装只监听 `127.0.0.1:8787`，真实接口默认关闭。

## 2. 通过 SSH 设置管理密码

在自己的电脑上保持以下隧道运行：

```sh
ssh -N -L 127.0.0.1:8788:127.0.0.1:8787 YOUR_SSH_USER@YOUR_SERVER
```

打开 `http://127.0.0.1:8788`，进入“管理登录”，设置 14–128 位管理密码。`SETUP` 只允许回环来源的开发模式，公网生产模式会拒绝使用它。

需要真实采集时，在服务器编辑 `/etc/yunjian-monitor/runtime.env` 将 `ENABLE_JD_LEGACY=false` 改成 `true`，仅重启本应用。随后通过网页添加本人授权的 TGT / WSKEY：

```sh
sudo systemctl restart yunjian-monitor.service
```

配置和数据库中的密码散列由服务读取；不要输出配置内容、数据库或请求头用于排错。

## 3. 选择 HTTPS 入口

先将自己的域名解析到服务器。`monitor.example.com` 是需要替换的示例域名。

### 已有反向代理

在现有反向代理中增加一个独立域名，将请求转发到 `http://127.0.0.1:8787`，并由代理覆盖 `X-Real-IP`。例如 Caddy 的站点配置：

```caddyfile
monitor.example.com {
    reverse_proxy 127.0.0.1:8787 {
        header_up X-Real-IP {remote_host}
    }
}
```

按现有代理流程验证配置并平滑加载；不要为了部署本项目停止其他服务。对应网站来源配置为 `https://monitor.example.com`。

### 独立 8443 入口

如果 443 已由其他服务使用，且 80、8443 均空闲，可使用仓库中的 `deploy/Caddyfile` 与 `yunjian-proxy.service`：

1. 从 [Caddy 官方安装说明](https://caddyserver.com/docs/install#static-binaries)取得适合服务器的静态二进制，并按官方说明校验。这里采用独立二进制，避免包安装时自动启动默认的 80/443 服务。
2. 将它放在 `/opt/yunjian-monitor/proxy/caddy`，权限 755。
3. 创建独立系统账户 `yunjian-proxy`，以及其拥有的 `/var/lib/yunjian-proxy`，目录权限 700。
4. 将 `deploy/Caddyfile` 中的 `monitor.example.com` 全部替换为自己的域名，保存到 `/etc/yunjian-proxy/Caddyfile`。配置目录需可被代理用户读取，配置文件 644。
5. 将 `deploy/yunjian-proxy.service` 安装为 `/etc/systemd/system/yunjian-proxy.service`，验证 Caddy 配置后启用。
6. 根据现有防火墙与云安全组规则，仅放行 TCP 80 和 8443，保留其他规则。

```sh
sudo /opt/yunjian-monitor/proxy/caddy validate --config /etc/yunjian-proxy/Caddyfile --adapter caddyfile
sudo systemctl daemon-reload
sudo systemctl enable --now yunjian-proxy.service
```

80 用于 HTTP-01 证书验证及跳转，HTTPS 在 8443。配置禁用 TLS-ALPN 验证，不占用 443；访问地址需要带 `:8443`。若 80 已被其他服务占用，应使用已有代理，或单独设计证书验证方案，不要强占端口。

## 4. 配置应用的公网来源

在完成首次管理密码设置后，运行以下工具。它从已有数据库读取当前管理密码散列，保留原加密密钥，写入生产模式与完整 HTTPS 来源，不输出秘密：

```sh
sudo /opt/yunjian-monitor/node/bin/node /opt/yunjian-monitor/app/scripts/configure-public.mjs /etc/yunjian-monitor/runtime.env https://monitor.example.com:8443
sudo systemctl restart yunjian-monitor.service
```

使用默认 443 反代时，将最后一个参数改为 `https://monitor.example.com`。来源地址不能带末尾 `/` 或路径，且必须与浏览器地址完全一致；配置错误会导致修改请求的来源校验失败。

公网配置完成后，可以关闭 SSH 隧道。请先验证 HTTPS 证书、管理登录和数据更新，再使用真实凭据。

## 5. 检查与维护

```sh
sudo systemctl status yunjian-monitor.service
sudo systemctl list-timers yunjian-backup.timer
curl --fail http://127.0.0.1:8787/healthz
sudo systemctl start yunjian-backup.service
```

备份每天北京时间 04:20 后随机延迟至多五分钟运行，设置页显示最近成功校验时间。应用的默认限制为最多 192 MB 内存、15% 单核 CPU 配额；可以依据自己的设备数量调整本项目专用 unit。

停止采集只需停止 `yunjian-monitor.service`。不要公开 `.env`、`runtime.env`、数据库、备份、证书私钥或抓包。恢复必须同时保留原加密配置和数据库副本，见[备份、恢复与升级](恢复与升级.md)。
